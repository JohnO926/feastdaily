# Feast Daily

A native iOS app that gets people reading scripture every day by racing a shared, secret daily alarm. Product
requirements are in [feast-daily-requirements.md](feast-daily-requirements.md).

| Path | What it is |
| --- | --- |
| `app/` | SwiftUI app, widget extension and tests. The Xcode project is generated by XcodeGen from `app/project.yml`. |
| `app/Packages/FeastCore/` | Shared Swift package: day model, verified reading timer, status resolver, API models, widget snapshot, scripture database access. Tested with `swift test`, no simulator needed. |
| `server/` | Next.js API on Vercel with Neon Postgres. The server is the only source of truth for feasts, missed meals and streaks. See `server/API.md`. |
| `tools/` | Scripture pipeline: converts the public domain Scriptures in JSON (git submodule) into the bundled SQLite with full-text search. |

## Setup

```sh
git submodule update --init          # scripture source text
brew install xcodegen xcbeautify
cp app/Config/Local.example.xcconfig app/Config/Local.xcconfig   # then fill in DEVELOPMENT_TEAM
```

Built with Xcode 27. If `xcode-select -p` shows the Command Line Tools, either run
`sudo xcode-select -s /Applications/Xcode.app` or rely on the Makefile, which sets `DEVELOPER_DIR` itself.

## Everyday commands

```sh
make db             # rebuild app/FeastDaily/Resources/scriptures.sqlite and print the spot-check list
make test-core      # FeastCore + FeastScripture tests
make run-sim        # build, install and launch on the iPhone 18 Pro simulator
make test-app       # app unit and UI smoke tests
make server-dev     # Postgres in Docker + API on http://localhost:3000
make server-test    # backend unit and DB tests
```

Build output goes to `~/Library/Caches/FeastDaily`, not the project folder. This folder sits in an iCloud-synced
Desktop, and iCloud tags files with extended attributes that make codesign fail.

## Running on your iPhone (free Personal Team)

1. Open Xcode once, Settings > Accounts, select your Apple ID so Xcode fetches the Personal Team.
2. Put the 10-character team ID in `app/Config/Local.xcconfig` as `DEVELOPMENT_TEAM`.
3. Set `API_BASE_URL` to your Mac's LAN address (for example `http://192.168.1.20:3000`) or a deployed URL.
4. On the phone: Settings > Privacy & Security > Developer Mode on.
5. `make build-device install-device`, then trust the developer under Settings > General > VPN & Device Management.

Free-tier builds expire after 7 days. Rebuild and reinstall weekly.

Without the paid Apple Developer Program there is no push, so the daily alarm is simulated with a local
notification (`ALARM_MODE = LOCAL_SIM`). With the server's `DEV_REVEAL_ALARM=true`, the app schedules that local
notification at the real secret time, so it fires at the instant the server scores against.

## Rules worth knowing

- A day is a feast if verified reading reaches the goal before the alarm instant. Otherwise it's a missed meal.
- "I read today" (self-report) counts only if tapped before the alarm. After the alarm it's a miss.
- The reader's timer only counts while the reader is visible, with a tap or scroll at least once a minute, and
  ignores page turns faster than about 3 seconds per screen.
- Goal changes take effect at the next rollover.

## Content

Verse text is the public domain edition from [Scriptures in JSON](https://bencrowder.net/scriptures-in-json/) by
Ben Crowder. Footnotes, chapter summaries and other copyrighted material are not included, and the app deep links
to Gospel Library for study. The app is independent and must not use Church names, logos or official-looking
branding.

`make db` prints the verses changed in the 2013 edition for a manual spot check. The first run found that
2 Nephi 4:23 still reads "night-time", although the source changelog lists it as corrected to "nighttime". Check
the rest against the current edition before launch.
